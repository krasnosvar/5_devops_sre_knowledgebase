# 08. Hardware Inventory

## Зачем
Чтобы планировать замену дисков, обновлять firmware и понимать, на чём
реально работает сервис, нужен точный учёт железа: модели CPU, объём и
тип памяти, диски и их SMART-состояние, сетевые карты, GPU. Тема даёт
команды для сбора этих данных и путь к автоматической инвентаризации в
DCIM-системе (Netbox).

## Файлы
- [01_theory/hardware_inventory.md](./01_theory/hardware_inventory.md) —
  `dmidecode`, `lshw`, `lscpu`; диски, NVMe и критичные SMART-атрибуты;
  сетевые карты; PCIe и GPU; обновление firmware через `fwupd` и
  вендорские утилиты; мониторинг железа; Netbox.
- [02_examples/inventory.sh](./02_examples/inventory.sh) — собирает
  сведения о сервере (ОС, CPU, память, диски, сеть, серийный номер) в
  JSON. Запускается на любой Linux-машине; для полей из `dmidecode`
  нужен root, без него они будут пустыми.

Без упражнений с ответами: команды и пример выполняются на любой
Linux-машине (🐳 Tier 1 / 🖥 Tier 2), отдельные задания не нужны.

## Как проходить
1. Прочитать теорию и выполнить команды на своей машине или VM.
2. Запустить `bash inventory.sh /tmp/inventory.json` сначала обычным
   пользователем, потом через `sudo` и сравнить поля.
3. Посмотреть SMART своих дисков (`smartctl -a`) и найти атрибуты из
   списка «критичных».

## Когда двигаться дальше
- Можете без подсказки узнать модель CPU, число сокетов, тип памяти и
  серийный номер сервера.
- Можете по SMART-атрибутам решить, пора ли менять диск.
- Понимаете, зачем выгружать инвентаризацию в DCIM, а не хранить в
  таблице.
