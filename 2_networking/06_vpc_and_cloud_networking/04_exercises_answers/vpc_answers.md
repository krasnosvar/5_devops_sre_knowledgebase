# Ответы — упражнения VPC и облачная сеть

## Ответ 01
- `aws_vpc.main` → "networking-lab" VPC в консоли, CIDR `10.0.0.0/16`.
- `aws_subnet.public` / `aws_subnet.private` → две подсети с тегами `public-a`/`private-a`.
- `aws_internet_gateway.igw` → Internet Gateways, привязан к VPC.
- `aws_nat_gateway.nat` → NAT Gateways, виден Elastic IP из `aws_eip.nat`.
- Route Tables (2 шт.) — у `public` маршрут `0.0.0.0/0 -> igw-...`, у `private` — `0.0.0.0/0 -> nat-...`.

## Ответ 02
Public-инстанс с `associate_public_ip_address = true` в подсети, чья route table указывает на Internet Gateway — доступен по SSH, если Security Group разрешает порт 22 с вашего IP. Private-инстанс без публичного IP физически не имеет адреса, по которому его можно было бы адресовать из интернета вообще — не вопрос правил файрвола, а того, что у него в принципе нет маршрутизируемого извне адреса. Единственный способ попасть на него — через Bastion host в public subnet или VPN/Session Manager.

## Ответ 03
Провайдер `aws` для ресурса `aws_security_group` (ingress/egress блоки) не имеет поля `action` вообще — только `from_port`/`to_port`/`protocol`/`cidr_blocks`, что технически означает Allow (Terraform это подтвердит ошибкой при попытке добавить несуществующий атрибут). Это соответствует реальному API AWS: Security Group — allow-only механизм. Явный Deny доступен только через `aws_network_acl`, где у каждого правила (`ingress`/`egress` блока) обязательное поле `action = "allow"` или `"deny"` — именно поэтому в `main.tf` правило с `rule_no = 90` и `action = "deny"` физически возможно только в NACL, а не в Security Group.

## Ответ 04
На момент написания (ориентировочно, сверяйте актуальные цены): NAT Gateway в большинстве регионов AWS стоит около $0.045/час + $0.045/GB обработанного трафика. Круглосуточно за месяц (~730 часов) это ~$33 только за время работы, плюс 100GB трафика — ещё ~$4.5, итого около **$37-40/месяц** за один NAT Gateway. Это одна из самых частых причин неожиданно большого облачного счёта — NAT Gateway тарифицируется независимо от того, используется ли он активно, и команды часто забывают, что каждая private-подсеть в проде обычно требует свой NAT Gateway на зону доступности (для отказоустойчивости), что кратно увеличивает эту стоимость.
