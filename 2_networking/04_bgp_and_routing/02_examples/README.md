# Пример: два FRRouting-роутера, реальный BGP peering

Демонстрационная, не структурированная как упражнение (см. план раздела — BGP
не входит в подразделы с формальными упражнениями). Два контейнера FRRouting
в разных автономных системах (AS64500 и AS64501), каждый анонсирует свою
подсеть — можно вживую посмотреть на AS Path, next-hop и таблицу маршрутов.

```bash
docker compose up -d
sleep 10   # BGP session establishment + первый обмен UPDATE

# Полная BGP-таблица router1 — должны быть ОБЕ подсети:
# своя (203.0.113.0/24, weight 32768) и чужая (198.51.100.0/24, через AS64501)
docker compose exec router1 vtysh -c "show ip bgp"

# Реальный маршрут в таблице маршрутизации ядра, установленный через BGP:
docker compose exec router1 vtysh -c "show ip route"

docker compose down
```

## Два реальных гочтa FRR, из-за которых peering "молча" не работает

Оба варианта проявляются одинаково: BGP-сессия в статусе `Established`,
`MsgRcvd`/`MsgSent` растут, но `show ip bgp` каждого роутера видит только
СВОЮ собственную подсеть — маршрут соседа не появляется.

1. **`bgp network import-check` (включён по умолчанию)** — директива
   `network 203.0.113.0/24` в конфиге BGP анонсирует подсеть, ТОЛЬКО если
   она уже существует как валидный маршрут в таблице маршрутизации (реальный
   интерфейс/статический маршрут). Внутри контейнера-лабы такого маршрута
   физически нет — анонс молча не отправляется. Исправление: `no bgp network
   import-check` (в проде используют осторожно — эта проверка защищает от
   анонса несуществующих сетей по ошибке).

2. **`bgp ebgp-requires-policy` (включён по умолчанию, RFC 8212)** — начиная
   с определённой версии FRR требует явную inbound/outbound policy
   (route-map/prefix-list) на каждого eBGP-соседа, иначе **все** входящие и
   исходящие обновления отбрасываются: `show ip bgp neighbors ... `покажет
   `Inbound updates discarded due to missing policy`. Для учебной лабы (не
   для прода!) отключается `no bgp ebgp-requires-policy`.

Оба видны в диагностике: `show ip bgp neighbors <ip>` → секция "For address
family: IPv4 Unicast" прямо называет причину.
