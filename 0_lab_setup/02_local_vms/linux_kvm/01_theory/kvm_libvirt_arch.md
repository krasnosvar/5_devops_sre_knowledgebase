# KVM + QEMU + libvirt — архитектура

## Стек виртуализации на Linux

```
┌─────────────────────────────────────┐
│  Ваши инструменты                   │
│  terraform (libvirt provider)       │
│  virsh / virt-manager               │
└─────────────┬───────────────────────┘
              │ libvirt API (UNIX socket)
┌─────────────▼───────────────────────┐
│  libvirtd — демон управления        │
│  Управляет: VM, сети, storage       │
└─────────────┬───────────────────────┘
              │ запускает
┌─────────────▼───────────────────────┐
│  QEMU — эмулятор устройств          │
│  Эмулирует: диск, сеть, BIOS, USB  │
└─────────────┬───────────────────────┘
              │ использует
┌─────────────▼───────────────────────┐
│  KVM (kernel module)                │
│  Даёт доступ к аппаратной          │
│  виртуализации (Intel VT-x, AMD-V)  │
└─────────────────────────────────────┘
```

**KVM** — модуль ядра Linux (`/dev/kvm`). Превращает ядро в гипервизор.
Обеспечивает почти нативную производительность CPU для VM.

**QEMU** — эмулятор, который запускается как обычный процесс. Эмулирует
железо (диск, сеть, видео). Без KVM работает медленно (чистая эмуляция),
с KVM — быстро (аппаратное ускорение CPU, только эмуляция устройств).

**libvirt** — абстракция поверх QEMU/KVM. Управляет lifecycle VM, сетями
и storage pool через единое API. Именно с ним работает Terraform.

## Сетевые режимы

**NAT (virbr0)** — VM получает адрес из 192.168.122.0/24, выходит в
интернет через NAT, с хоста доступна, из внешней сети — нет.
Используется по умолчанию. Подходит для большинства лаб.

**Bridge** — VM напрямую в физическую сеть, получает адрес от DHCP
роутера. Видна из любого устройства в LAN. Нужна для лаб с внешним доступом.

**Isolated** — VM только между собой, без доступа наружу. Для закрытых стендов.

## Storage

**qcow2** — формат образа дисков QEMU. Поддерживает copy-on-write
(снапшоты), сжатие, тонкое выделение места (файл растёт по мере записи).

**Backing file (базовый образ)** — один master qcow2 образ (например, Ubuntu 24.04)
+ N дельта-образов для каждой VM. Экономит место: 5 VM на 1 базовом образе
занимают гораздо меньше чем 5 полных копий.

```
ubuntu-24.04-base.qcow2  (read-only, ~1 GB)
    ├── vm-node-1.qcow2  (delta, ~200 MB)
    ├── vm-node-2.qcow2  (delta, ~200 MB)
    └── vm-node-3.qcow2  (delta, ~200 MB)
```

## cloud-init

Стандарт инициализации cloud VM (поддерживается Ubuntu, Fedora, RHEL, Debian).
При первом старте VM читает `user-data` и `meta-data` из ISO-образа и выполняет:
- создание пользователей и установку SSH ключей
- настройку hostname
- выполнение произвольных команд (runcmd)
- установку пакетов

Именно cloud-init позволяет создать VM через Terraform и сразу получить
доступ по SSH без ручной настройки.
