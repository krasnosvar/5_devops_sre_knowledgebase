## 1. Проблемы качества данных в ML и четыре измерения Data Quality

В обычном микросервисе некорректный входной JSON сразу вызывает исключение
`422 Unprocessable Entity` или `NullPointerException`. В пайплайне
машинного обучения или RAG «сломанные» данные гораздо коварнее — они не
вызывают падения процесса, а **тихо разрушают математику модели**:

1. **Completeness (Полнота):** отсутствие `NULL`, `NaN` и пустых строк.
   *Пример из жизни:* пользователь сфотографировал медицинскую выписку при
   плохом освещении, OCR вернул всего 3 неразборчивых символа. Если такой
   документ попадёт в обучение или векторный индекс `Qdrant`, он создаст
   «мусорный» вектор, притягивающий к себе нерелевантные запросы.
2. **Validity (Валидность и соблюдение схемы — Schema Compliance):**
   соответствие типам, допустимым множествам (`enum`) и регулярным
   выражениям.
   *Пример:* в поле `category` вместо `medicine` попала строка `Врачи`,
   из-за чего в классификаторе неожиданно появился 5-й класс из одного
   примера.
3. **Uniqueness (Уникальность и защита от Data Leakage):**
   отсутствие полных и нечётких дубликатов.
   *Критическая ловушка:* если в датасете есть дубликаты одного и того же
   документа, то при случайном разбиении `train_test_split` одна копия
   попадёт в `train`, а вторая — в `test`. Модель просто запомнит текст
   наизусть (Data Leakage / утечка данных), покажет на тесте ложные `F1 =
   0.99`, а на новых документах в продакшне провалится.
4. **Consistency (Логическая непротиворечивость):**
   соблюдение кросс-полевых инвариантов (например, дата окончания действия
   справки не может быть меньше даты её выдачи).

## 2. Контрактная валидация данных: `Pydantic` vs `Pandera` vs `Great Expectations`

Чтобы не пускать битые данные в обучение и индекс, на входе пайплайна
ставятся **Data Contracts (контракты данных)**. В экосистеме Python для
этого применяются три разных инструмента, каждый на своём уровне:

### 2.1 `Pydantic` — уровень одиночных записей и API / LLM Output
`Pydantic v2` (ядро написано на Rust) проверяет один объект (JSON-запрос
в `FastAPI` или структурированный ответ от локальной LLM):

```python
from datetime import date
from typing import Literal
from pydantic import BaseModel, Field


class DocumentMetadata(BaseModel):
    doc_id: str = Field(min_length=4, max_length=64)
    category: Literal["medicine", "gov", "finance", "notes", "offtopic"]
    doc_date: date
    summary: str = Field(min_length=15, max_length=500)
```

### 2.2 `Pandera` — векторная проверка таблиц (`pandas` / `polars`)
Когда нужно проверить таблицу на 100 000 строк перед обучением, прогонять
её построчно через `Pydantic` слишком медленно. **`Pandera`** выполняет
векторные проверки сразу по целым колонкам `DataFrame` (в десятки раз
быстрее) и позволяет писать статистические гипотезы прямо в схеме:

```python
import pandera as pa
from pandera import Column, Check, DataFrameSchema

docs_schema = DataFrameSchema(
    {
        "doc_id": Column(str, unique=True, nullable=False),
        "category": Column(
            str,
            Check.isin(["medicine", "gov", "finance", "notes", "offtopic"]),
        ),
        "text": Column(
            str,
            [
                Check.str_length(min_value=20, max_value=50000),
                # Доля непустых осмысленных текстов должна быть 100%
                Check(lambda s: (~s.str.isspace()).all(), error="Пустой текст после OCR"),
            ],
        ),
    },
    strict=True,
)
```

### 2.3 `Great Expectations` (GX) — витрины данных и HTML Data Docs
Если данные лежат не в локальном файле, а в корпоративном хранилище
(`PostgreSQL`, `ClickHouse`, `Snowflake`, `Spark`), выгружать терабайты в
память Python ради проверки нельзя. **`Great Expectations`** транслирует
правила (`Expectation Suite`, например `expect_column_values_to_not_be_null`)
в SQL-запросы, исполняет их внутри самой СУБД и генерирует наглядный
HTML-портал (**Data Docs**) со светофорами качества для команды аналитиков
и дата-инженеров.

## 3. Как устроен `DVC` (Data Version Control) под капотом

Git великолепно хранит текстовый код, но при коммите гигабайтных датасетов
или весов моделей репозиторий раздувается и перестаёт клонироваться.
**`DVC`** решает эту проблему, связывая Git с внешним объектным хранилищем
(`S3` / `SeaweedFS` / `MinIO` / `SSH`).

### 3.1 Анатомия `.dvc`-файла и контент-адресуемого кэша
Когда вы выполняете `dvc add data/corpus.parquet`:
1. `DVC` вычисляет `MD5`-хэш файла (например, `e4d909c290d0fb1ca068ffaddf22cbd0`).
2. Сам тяжёлый файл перемещается в локальный кэш `.dvc/cache/files/md5/e4/d909c2...`,
   а в рабочей директории `data/corpus.parquet` создаётся жёсткая ссылка
   (`hardlink` или `reflink`) на этот кэш.
3. Путь `data/corpus.parquet` автоматически добавляется в `.gitignore`.
4. Рядом создаётся крошечный текстовый метафайл `data/corpus.parquet.dvc`
   (весом 120 байт), который коммитится в обычный **Git**:

```yaml
outs:
- md5: e4d909c290d0fb1ca068ffaddf22cbd0
  size: 48291042
  hash: md5
  path: corpus.parquet
```

Команда `dvc push` копирует блобы из `.dvc/cache/` в бакет S3 (`SeaweedFS`),
а `dvc pull` после `git checkout v1.0` скачивает из S3 ровно ту версию
датасета, чей `md5` записан в `.dvc`-файле этого Git-коммита!

## 4. Декларативные пайплайны `dvc.yaml`, `dvc.lock` и команда `dvc repro`

Помимо хранения файлов, `DVC` работает как аналог `Make` для машинного
обучения. В файле `dvc.yaml` описывается ориентированный ациклический граф
(DAG) шагов, где у каждого шага явно указаны:
- `cmd` — команда запуска;
- `deps` — входные данные и скрипты кода;
- `params` — гиперпараметры из `params.yaml`;
- `outs` — выходные артефакты (например, `model.onnx`);
- `metrics` — JSON-файл с метриками (`metrics.json`).

При запуске `dvc repro`:
1. `DVC` сверяет текущие `MD5`-хэши всех `deps`, `params` и `outs` со
   значениями, зафиксированными в файле **`dvc.lock`**.
2. Если входной датасет и код шага валидации не менялись, а изменился
   только гиперпараметр обучения в `params.yaml` — `DVC` пропустит валидацию
   и перезапустит **только** шаг обучения и оценки!

## 5. Проектирование эталонного датасета для личного архива документов

В папке `02_examples/golden_docs_dataset.json` мы создаём фундамент для
всех последующих глав нашего пет-проекта — синтетический набор документов
по 5 классам:
- `medicine` — анализы крови (гемоглобин, ферритин, витамин D), заключения
  профильных врачей (гастроэнтеролог, невролог), рецепты.
- `gov` — справки из МФЦ, налоговые уведомления ФНС, выписки ЕГРН,
  заявления с Госуслуг.
- `finance` — квитанции ЖКХ, полисы ОСАГО/ДМС, кассовые чеки за лечение
  (пограничный случай для проверки точности классификатора!).
- `notes` — личные текстовые заметки, списки покупок, конспекты.
- `offtopic` — случайные запросы не по документам и попытки prompt
  injection (должны отсекаться роутером).

## 6. Типовые вопросы на собеседовании (Interview Q&A)

**1. Чем концептуально отличается валидация данных через `Pydantic` от
валидации через `Pandera`?**
*Ответ:* `Pydantic` предназначен для построчной/объектной валидации и
парсинга структур данных в рантайме (например, одиночного JSON в HTTP-запросе
или ответа LLM). `Pandera` работает с колоночными табличными структурами
(`pandas.DataFrame`, `polars.DataFrame`) и выполняет векторизованные
проверки сразу над целыми массивами и статистическими распределениями
колонок (среднее, квантили, доля `NULL`), что на порядки быстрее на
больших выборках.

**2. Что такое Data Leakage (утечка данных) из-за дубликатов при подготовке
датасета и как её предотвратить?**
*Ответ:* Если в исходном наборе данных присутствуют полные или почти
полные дубликаты документов, то при случайном разбиении на обучающую и
тестовую выборки один и тот же текст попадёт и в `train`, и в `test`.
Модель покажет завышенную метрику на тесте за счёт запоминания, но не
обобщит знания. Предотвращается дедупликацией по хэшу нормализованного
текста (или MinHash/LSH для нечётких дубликатов) и разбиением по группам/времени
до обучения.

**3. Что физически хранится в Git, а что в S3 при использовании `DVC`?**
*Ответ:* В Git хранятся только легковесные текстовые YAML-файлы (`.dvc`,
`dvc.yaml`, `dvc.lock`), содержащие `MD5`-хэши, размеры и пути к данным.
Сами бинарные файлы датасетов и моделей переименовываются по своему `MD5`
хэшу (например, `files/md5/ab/cd1234...`) и хранятся в удалённом бакете
S3.

**4. Как `DVC` избегает дублирования 50-гигабайтного датасета на диске
между скрытой папкой `.dvc/cache` и рабочей папкой `data/`?**
*Ответ:* При настройке `dvc config cache.type reflink,hardlink,symlink`
утилита не копирует байты из `.dvc/cache` в рабочую директорию, а создаёт
Copy-on-Write ссылку (`reflink` на Btrfs/XFS/APFS) или жёсткую ссылку
(`hardlink`). Оба пути указывают на одни и те же блоки диска.

**5. В чём разница между файлами `dvc.yaml` и `dvc.lock`?**
*Ответ:* `dvc.yaml` пишется человеком и описывает структуру пайплайна
(команды, имена входных и выходных файлов). `dvc.lock` генерируется
автоматически после выполнения `dvc repro` и фиксирует точные `MD5`/`SHA256`
хэши всех входов, параметров и полученных выходов для конкретного запуска
(аналог пары `pyproject.toml` и `uv.lock`).

**6. Как команда `dvc repro` понимает, какие стадии пайплайна нужно
перезапустить, а какие можно взять из кэша?**
*Ответ:* Она строит граф зависимостей (DAG) из `dvc.yaml`, вычисляет
текущие хэши всех входных файлов (`deps`), скриптов кода и значений из
`params.yaml` и сравнивает их с записью в `dvc.lock`. Если хэши стадии
совпадают, стадия пропускается (`Stage is cached`).

**7. Когда в проекте оправдано внедрение тяжёлого фреймворка `Great
Expectations` вместо лёгких схем `Pandera`?**
*Ответ:* Когда данные лежат в промышленных реляционных или колоночных
хранилищах (`PostgreSQL`, `ClickHouse`, `BigQuery`, `Spark`) и объём не
позволяет выгрузить их в память одного Python-процесса, а также когда
бизнесу и дата-инженерам требуются автоматические визуальные отчёты о
качестве витрин (**HTML Data Docs**) и интеграция с `Apache Airflow`.

**8. В чём разница между Schema Drift и Data Drift?**
*Ответ:* **Schema Drift** — это структурное нарушение контракта данных
(исчезла колонка, тип поля изменился с `float` на `string`, пришло новое
неизвестное значение `enum`). Он ловится детерминированными валидаторами
(`Pandera`, `Pydantic`) на входе и блокирует пайплайн. **Data Drift** —
схема и типы соблюдены (все поля `float` на месте), но изменилось само
статистическое распределение значений внутри них (ловится статистическими
тестами `PSI` и `KS` в `Evidently`).

**9. Почему разбиение датасета на `train` и `test` для документов с
временными метками лучше делать по времени (Time-based split), а не
случайно (`random split`)?**
*Ответ:* В реальной жизни модель обучается на документах прошлого и
предсказывает категории документов будущего (где появляются новые шаблоны
справок и новые формулировки). Случайный сплит перемешивает будущее с
прошлым и даёт оптимистичную оценку, скрывая деградацию модели во времени.

**10. Как проверить качество текстовых данных после OCR перед отправкой
их в векторную базу `Qdrant` для RAG?**
*Ответ:* Написать фильтр валидации текста: проверить минимальную длину
строки, долю буквенно-цифровых символов к спецсимволам (если в строке 60%
символов `@#$%^~`, значит OCR прочитал шум на скане вместо текста),
наличие корректной кодировки UTF-8 и отсутствие дублирующихся страниц.
