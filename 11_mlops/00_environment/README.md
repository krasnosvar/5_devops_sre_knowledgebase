# 00. Подготовка окружения MLOps и LLMOps

> Уже знакомы с темой? → [CHEATSHEET.md](./CHEATSHEET.md) — быстрый
> справочник команд `uv`, привязки P-ядер CPU, кэша моделей и `k3d`.

## Зачем

Главная причина, почему локальные ML/LLM-стенды «тормозят», забивают диск
дубликатами весов по 15 ГБ или падают при установке пакетов — неправильно
настроенное базовое окружение:

1. На хосте стоит самый свежий Python (например, 3.14), для которого ещё
   нет готовых C++/Rust-колёс (`manylinux wheel`) у `onnxruntime`, `torch`
   или `pyarrow`, и `pip` пытается полчаса компилировать их из исходников.
2. Контейнеры `llama.cpp`, `Ollama` и `Jupyter` при каждом перезапуске
   заново качают гигабайты моделей с Hugging Face вместо чтения из одного
   общего кэша на диске.
3. На гибридных процессорах (Intel Core Ultra 155H: 6 P-ядер + 8 E-ядер +
   2 LP-ядра) рантайм по умолчанию запускает 22 потока, из-за чего быстрые
   P-ядра простаивают на барьерах синхронизации, ожидая медленные E-ядра.
4. Личные документы (выписки врачей, госорганы) или тяжёлые веса `.gguf`
   случайно попадают в `git add .` и утекают в публичный репозиторий.

Эта глава один раз настраивает предсказуемый фундамент для всех остальных
модулей раздела.

## Как проходить

1. Прочитать [01_theory/environment_setup.md](./01_theory/environment_setup.md).
2. Запустить `./02_examples/check_env.sh` и проверить топологию P-ядер
   своего процессора и объём доступной RAM.
3. Создать общую директорию кэша моделей (`~/.cache/mlops-models`) и
   локальную папку для личных документов вне Git-репозитория.
4. Инициализировать окружение Python 3.12 через `uv` по примеру из
   `02_examples/pyproject.toml`.

## Когда двигаться дальше

- `uv run python --version` выводит `Python 3.12.x` независимо от системной
  версии Python в дистрибутиве Linux.
- Вы знаете номера логических потоков своих P-ядер и умеете ограничить
  ими процесс или контейнер (`taskset -c` / `cpuset`).
- Папка кэша моделей и папка личных документов вынесены за пределы
  репозитория и закрыты в `.gitignore`.
