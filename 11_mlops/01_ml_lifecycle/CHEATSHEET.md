## Этапы цикла и инструменты

| Этап | Артефакт на выходе | Классический MLOps | LLMOps |
| :--- | :--- | :--- | :--- |
| **1. Задача и Golden Set** | ТЗ + 30–50 эталонных пар `вход → ответ` | Метрика (`F1`, `ROC-AUC`) + бюджет `p99 latency` | Метрика (`Hit@K`, `Faithfulness`) + бюджет `$/1k req` |
| **2. Данные (Data Prep)** | Очищенный датасет / чанки | `Pandera`, `Great Expectations`, `DVC`, `Feast` | Парсинг PDF/OCR (`Docling`), чанкинг, `Qdrant` |
| **3. Эксперименты** | Залогированные запуски (Runs) | `MLflow`, `ClearML` (гиперпараметры, веса) | Промпты, выбор модели (`Qwen`/`Gemma`), LoRA SFT |
| **4. Оценка и Gate** | Отчёт + решение о промоушене | `pytest` инвариантов, `modelscan` (безопасность) | `promptfoo`, `RAGAS`, проверка на Golden Dataset |
| **5. Подача (Serving)** | Работающий API / батч-джоба | `ONNX Runtime`, `FastAPI`, `BentoML`, `KServe` | `llama.cpp`, `Ollama`, `vLLM`, `LiteLLM Gateway` |
| **6. Мониторинг** | Метрики и алерты в `Prometheus` | `Evidently` (`PSI`, `KS-тест` дрифта), latency | `Langfuse` (трейсы, токены), `Presidio` (PII) |
| **7. Переобучение (CT)** | Новая версия модели в Registry | DAG в `Airflow` / `Prefect` по расписанию или дрифту | Обновление индекса `Qdrant` / дообучение адаптера |

## Уровни зрелости MLOps (Google / Microsoft Maturity Model)

| Уровень | Как устроена работа | Что деплоится вручную, а что автоматически | Главный риск |
| :--- | :--- | :--- | :--- |
| **Level 0 (Ручной)** | Обучение в Jupyter Notebook на ноутбуке DS; на выход отдаётся файл `.pkl` | Всё вручную: нет воспроизводимости, нет CI/CD, нет автопереобучения | Модель «умирает» при первом изменении данных или увольнении автора |
| **Level 1 (ML Pipeline Automation / CT)** | В прод деплоится не файл весов, а **автоматический пайплайн обучения** (`Airflow`/`Prefect`) | Переобучение (Continuous Training) по расписанию или триггеру дрифта автоматизировано | Сам код пайплайна и фичей всё ещё выкатывается без полноценного CI/CD |
| **Level 2 (CI/CD + CT Automation)** | Полный GitOps и CI/CD для кода пайплайнов, схем данных, контейнеров и промптов | Коммит в Git → автотесты (`pytest`/`promptfoo`) → сборка пайплайна → CT → Canary-релиз | Требует развитой платформы (окупается при 5+ моделях в продакшне) |

## Главные метрики ML для инженера инфраструктуры

| Метрика | Что измеряет | ⚠️ Ловушка |
| :--- | :--- | :--- |
| `Accuracy` | Доля всех правильных ответов | Бесполезна при дисбалансе: если фродовых транзакций 1%, константа «всегда 0» даёт 99% Accuracy |
| `Precision` (Точность) | Доля реальных срабатываний среди всех, кого модель назвала классом `1` | Высокий Precision при низком Recall значит, что модель боится срабатывать и пропускает 80% случаев |
| `Recall` (Полнота) | Доля найденных объектов класса `1` из всех реально существующих | Критична в медицине и ИБ (лучше лишний раз перепроверить анализ, чем пропустить болезнь) |
| `F1-score` | Гармоническое среднее `Precision` и `Recall` | Хороша как единое число для Quality Gate классификатора |
| `Hit@K` / `MRR` | Нашёл ли векторный поиск правильный документ в топ-K выдачи (для RAG) | Если `Hit@5` низкий, менять LLM или промпт бесполезно — проблема в чанкинге или эмбеддингах |
