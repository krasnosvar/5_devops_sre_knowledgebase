## Репликация и шардирование баз данных

| Задача / Паттерн | Механизм | Главный компромисс / Ловушка |
| :--- | :--- | :--- |
| Масштабирование чтения (`SELECT`) | Single-Leader + Read Replicas | ⚠️ Не масштабирует запись! Лаг репликации ломает Read-Your-Writes |
| Защита от потери данных (`RPO = 0`) | Кворумная синхронная репликация (`ANY 1 (r1, r2)`) | ⚠️ Только 1 синхронная реплика снижает доступность на запись при её сбое |
| Строгий кворум (Leaderless / Dynamo) | $W + R > N$ (например, $N=3, W=2, R=2$) | Пересечение записи и чтения минимум по 1 узлу со свежими данными |
| Масштабирование записи (`INSERT`) | Горизонтальное шардирование по ключу или LSM-Tree | Потеря кросс-шардовых `JOIN`, запросы без ключа дают `Scatter-Gather` |
| Consistent Hashing | Кольцо хэшей + **100–256 виртуальных узлов (`vnodes`)** | При добавлении/падении 1 из $N$ серверов переезжает только $1/N$ ключей |
| Распределённые транзакции | **Saga** (Orchestration / Choreography) с компенсациями | ⚠️ 2PC блокирует строки; в Saga нет изоляции (`I` из ACID) → нужны холды/статусы |

## Брокеры сообщений: Kafka vs RabbitMQ vs NATS

| Критерий | Apache Kafka | RabbitMQ | NATS / JetStream |
| :--- | :--- | :--- | :--- |
| Модель хранения | Неизменяемый лог на диске (Replay по `offset`) | Очередь (удаление сразу после `ACK`) | Сверхбыстрая Pub/Sub шина + стрим |
| Где гарантирован порядок? | ⚠️ **Только внутри одной партиции** (по `Partition Key`) | Внутри одной очереди (при 1 консьюмере) | Внутри субъекта/стрима |
| Лимит параллелизма чтения | Число воркеров группы $\le$ **числа партиций топика** $P$ | Любое число воркеров на очередь (нужен `prefetch_count`) | Любое число воркеров в Queue Group |
| Надёжная отправка из БД | **Transactional Outbox** (`INSERT` в БД + таблица `outbox` в 1 транзакции) | Transactional Outbox + Publisher Confirms | JetStream Ack + дедупликация по ID |
| Гарантия без дублей | `At-Least-Once` (ручной коммит после БД) + **Идемпотентный консьюмер (Inbox)** | `manual ack` + идемпотентность по `message_id` | `AckExplicit` + `Nats-Msg-Id` |

## Алгоритмы балансировки и паттерны отказоустойчивости

| Паттерн / Алгоритм | Как работает и зачем нужен |
| :--- | :--- |
| **Power of Two Choices (P2C)** | Выбирает 2 случайных узла и шлёт запрос на менее загруженный (быстро и без глобальной синхронизации) |
| **Token Bucket vs Leaky Bucket** | Token Bucket разрешает короткие легитимные **bursts**; Leaky Bucket выравнивает выход в ровную линию |
| **Sliding Window Counter** | Взвешенная сумма прошлого и текущего окна: решает проблему **2x трафика на стыке минут** Fixed Window |
| **Retries + Backoff + Full Jitter** | $\text{sleep} = \text{rand}(0, \min(T_{\text{cap}}, T_{\text{base}} \cdot 2^k))$ + **Retry Budget (10%)** + ретраи только на 1 слое! |
| **Circuit Breaker** | `CLOSED` → `OPEN` (мгновенный отказ за 0 мс при $>50\%$ ошибок) → `HALF-OPEN` (пробные запросы) |
| **Bulkhead (Переборки)** | Изолированные пулы потоков/соединений под каждый внешний сервис, чтобы сбой одного не повесил все остальные |
| **Graceful Shutdown в k8s** | `preStop: sleep 5` (дать `kube-proxy`/Envoy убрать IP из ротации) → `SIGTERM` → доработать активные запросы |

## Команды проверки репликации и очередей

| Задача | Команда |
| :--- | :--- |
| Лаг репликации PostgreSQL (в байтах WAL) | `psql -c "SELECT client_addr, state, pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) FROM pg_stat_replication;"` |
| Отставание Consumer Group в Kafka (`LAG`) | `kafka-consumer-groups.sh --bootstrap-server <host:9092> --describe --group <group>` |
| Список очередей и неподтверждённых сообщений в RabbitMQ | `rabbitmqctl list_queues name messages_ready messages_unacknowledged` |

## Симптом → куда смотреть

| Симптом | Куда смотреть |
| :--- | :--- |
| Пользователь сохранил форму, обновил страницу и не видит изменений | Лаг асинхронной реплики (Read-Your-Writes) → читать с мастера 5 с после записи |
| При моргании БД перезапустились сразу все 50 подов бэкенда | ⚠️ Проверка БД засунута в `livenessProbe` → убрать из `liveness`, оставить только процесс |
| При деплое новой версии в Kubernetes проскакивают `502 Bad Gateway` | Гонка удаления из `EndpointSlice` и `SIGTERM` → добавить `preStop: sleep 5` |
| Добавили 10 подов консьюмеров Kafka, а лаг не падает | Подов больше, чем партиций в топике (лишние поды сидят `Idle`) |
| При сбое БД нагрузка на неё выросла в 20 раз | Лавина ретраев (Retry Storm) без Jitter и на нескольких слоях стека одновременно |

> Проверка: синтаксис SQL и CLI-флагов проверен по документации PostgreSQL,
> Apache Kafka и RabbitMQ; не проверено: выполнение на живом кластере
> БД/брокера.
