## Монолит vs Модульный монолит vs Микросервисы

| Критерий | Монолит | Модульный монолит | Микросервисы |
| :--- | :--- | :--- | :--- |
| Единица деплоя | Один процесс/образ | Один процесс/образ | Независимый сервис на домен |
| Изоляция БД | Общие таблицы и `JOIN` | Разные схемы/префиксы без `JOIN` | Database-per-Service |
| Вызов соседа | В памяти (`~10 нс`) | В памяти через публичный интерфейс | По сети (`0.5–10 мс`, сериализация) |
| Транзакции | Локальные ACID | Локальные ACID (по модулю) | Saga / Outbox / Eventual Consistency |
| Когда выбирать | Прототип, малая команда | 80% систем, до 30–40 инженеров | 40+ инженеров, разный профиль нагрузки/SLA |

## Признаки распределённого монолита (⚠️ Антипаттерн)

| Симптом | Как исправить |
| :--- | :--- |
| Каскадный синхронный релиз нескольких сервисов | Контрактное версионирование, Backward Compatibility |
| Несколько сервисов ходят в одну БД | Выделить владельца таблиц, доступ только через API/события |
| Цепочка из 5–10 синхронных RPC на один запрос | Перевести на асинхронные события, агрегировать данные (CQRS) |
| Общая библиотека с доменной бизнес-логикой | Оставить в shared только чистые утилиты (логгер, трейсинг) |

## Внутренняя архитектура сервиса и DDD

| Паттерн / Блок | Суть и правило |
| :--- | :--- |
| Dependency Rule (Clean / Hexagonal) | Все зависимости в коде направлены **только внутрь** к домену; БД и HTTP — внешние адаптеры |
| Bounded Context (Стратегический DDD) | Смысловая граница модели и языка; правильная граница микросервиса или модуля |
| Anti-Corruption Layer (ACL) | Адаптер-переводчик на границе с легаси/внешним API, защищающий чистую модель домена |
| Entity vs Value Object | Entity имеет уникальный `ID` и меняется; Value Object определяется полями и строго неизменяем |
| Aggregate & Aggregate Root | Кластер объектов, изменяемый атомарно; ⚠️ **1 транзакция = 1 агрегат**, делать маленькими |
| CQRS | Разделение моделей записи (Commands) и чтения (Queries) |
| Event Sourcing | Хранение неизменяемого лога событий вместо текущего состояния (для аудита/леджеров) |

## Сравнение стилей API: REST vs gRPC vs GraphQL

| Параметр | REST (JSON) | gRPC (Protobuf / HTTP/2) | GraphQL |
| :--- | :--- | :--- | :--- |
| Основная ниша | Публичный API, внешние клиенты | Внутренний межсервис (East-West) | Мобильные и сложные Web-клиенты (BFF) |
| Идемпотентность | `GET`, `PUT`, `DELETE` — да; ⚠️ `POST` — нет (нужен `Idempotency-Key`) | Задаётся семантикой метода + ключ идемпотентности | Запросы (`query`) — да, мутации (`mutation`) — нет |
| Главная ловушка | Медленная `OFFSET`-пагинация → использовать Cursor/Keyset | ⚠️ L4 `ClusterIP` не балансирует HTTP/2 → нужен L7 прокси/headless | ⚠️ Проблема $N+1$ и глубокие DoS-запросы → `DataLoader` + Depth Limit |

## Диагностика сети, API и Service Discovery

| Задача | Команда |
| :--- | :--- |
| Число активных TCP-соединений на ноде | `ss -tan state established \| wc -l` |
| Ретрансмиты и таймауты TCP в цепочке сервисов | `nstat -az TcpRetransSegs TcpExtTCPTimeouts` |
| Проверить `EndpointSlice` сервиса в Kubernetes | `kubectl get endpointslices -l kubernetes.io/service-name=<svc>` |
| Вызов gRPC-метода из терминала (рефлексия) | `grpcurl -plaintext localhost:50051 list` |
| Замер таймингов HTTP-запроса (DNS, TLS, TTFB) | `curl -w "dns:%{time_namelookup} tls:%{time_appconnect} ttfb:%{time_starttransfer}\n" -o /dev/null -s <url>` |

## Симптом → куда смотреть

| Симптом | Куда смотреть |
| :--- | :--- |
| Новые поды gRPC-сервиса сидят с 0% CPU после HPA scale-out | L4-балансировка одного HTTP/2 соединения → включить L7 (Envoy) или headless service |
| Двойные списания при сетевых таймаутах | Ретраи `POST` без `Idempotency-Key` |
| Высокий счёт за сеть в облаке при микросервисах | Cross-AZ трафик → включить Topology Aware Routing |
| Медленная загрузка страниц на глубокой истории | `LIMIT ... OFFSET` → перевести на Keyset/Cursor пагинацию |

> Проверка: `ss`, `nstat`, `curl -w` выполнены локально (Linux);
> `kubectl get endpointslices` — синтаксис проверен по `kubectl --help`;
> не проверено: `grpcurl` (требует запущенный gRPC-сервер).
