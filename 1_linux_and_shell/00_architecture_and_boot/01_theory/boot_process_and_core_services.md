## 1. User Space и Kernel Space (Кольца защиты)

Современные процессоры аппаратно изолируют выполнение кода по уровням привилегий (Protection Rings).
В Linux используются только два кольца:
- **Ring 0 (Kernel Space, Ядро)**: Максимальные привилегии. Полный доступ к железу, памяти, прерываниям. Здесь работает ядро Linux и драйверы устройств.
- **Ring 3 (User Space, Пользовательское пространство)**: Ограниченные привилегии. Здесь работают все наши программы (bash, nginx, docker, базы данных).

**Системные вызовы (Syscalls):**
Программы из User Space не могут сами читать с диска или отправлять пакеты в сеть. Они вынуждены просить ядро сделать это за них через **системные вызовы** (например, `open()`, `read()`, `write()`, `clone()`). Переключение контекста из User Space в Kernel Space стоит дорого (сотни наносекунд), поэтому высоконагруженные системы (например, базы данных) стараются батчить I/O операции, чтобы реже переключаться.

## 2. Процесс загрузки Linux (Boot Process)

Загрузка Linux от кнопки питания до командной строки:

1. **BIOS / UEFI**: Оборудование подает питание. Прошивка материнской платы проводит самотестирование (POST), находит загрузочный диск и читает с него загрузчик.
2. **Bootloader (GRUB2)**: Загрузчик знает файловую систему и загружает в оперативную память (RAM) сам бинарный файл ядра (`vmlinuz-...`) и временный RAM-диск (`initramfs.img`).
3. **Kernel (Ядро)**: Ядро распаковывается в памяти, инициализирует базовое железо (CPU, память, шины) и монтирует `initramfs` как корень.
4. **initramfs (Initial RAM Filesystem)**: Это временная корневая файловая система в RAM. Она нужна, потому что ядро само по себе может не иметь драйверов для сложных RAID-массивов, LVM или зашифрованных дисков (LUKS), на которых лежит настоящая ОС. Скрипты внутри `initramfs` подгружают нужные модули (драйверы), собирают LVM/RAID, расшифровывают диск и монтируют *настоящий* корень (rootfs).
5. **PID 1 (systemd)**: Ядро переключает корень (pivot_root) с временного на настоящий жесткий диск и запускает первую программу в User Space с PID 1 — `systemd` (или `init`). `systemd` начинает параллельно поднимать все сервисы, сеть, монтировать остальные диски из `/etc/fstab` и запускать приглашение для входа (login prompt).

## 3. Удаленный доступ: SSH под капотом

**SSH (Secure Shell)** — протокол безопасного удаленного управления (порт 22).

**Как работает аутентификация по ключам:**
Основана на асимметричной криптографии (RSA, Ed25519). 
1. У вас есть пара: **Private Key** (никому не даем, лежит на клиенте) и **Public Key** (копируем на сервер в `~/.ssh/authorized_keys`).
2. При попытке входа сервер берет случайную строку (challenge) и шифрует ее вашим *Публичным ключом*.
3. Сервер отправляет этот шифр вам. Только обладатель *Приватного ключа* может это расшифровать.
4. Клиент расшифровывает строку и отправляет серверу (или хэш от нее). Сервер видит, что строка совпала — доступ разрешен.

**SSH-Agent и Forwarding:**
Если вам нужно зайти с вашего ноутбука на Server A, а с него на Server B (оба требуют ваш ключ). Оставлять приватный ключ на Server A опасно. `ssh-agent` хранит расшифрованный ключ в памяти ноутбука. `ForwardAgent yes` пробрасывает UNIX-сокет агента на Server A, позволяя Server A авторизоваться на Server B, используя ключ, лежащий в RAM вашего ноутбука.

## 4. Синхронизация времени: NTP и Chrony

Точное время критично для распределенных систем, баз данных (Cassandra, Spanner), генерации JWT-токенов и логов. Без синхронизации локальные часы серверов неизбежно "уплывают" (Clock Drift).

- **NTP (Network Time Protocol, UDP 123)** — иерархический протокол. Серверы делятся на *Стратумы (Stratum)*. Stratum 0 — атомные часы (GPS), Stratum 1 — серверы, напрямую к ним подключенные, Stratum 2 — серверы, берущие время у Stratum 1 (например, `pool.ntp.org`).
- В современных Linux стандартом стал демон **Chrony** (`chronyd`). Он работает гораздо точнее и быстрее синхронизирует время, чем старый `ntpd`, особенно на виртуалках, где время может резко скакать.
- Время никогда не переводится назад "скачком" (чтобы не сломать таймеры в БД). Вместо этого Chrony **замедляет или ускоряет ход локальных часов (slew)**, пока они не синхронизируются с мировым временем.

## 5. Типовые вопросы на собеседовании (Interview Q&A)

**1. В чем разница между Kernel Space и User Space? Зачем такое разделение?**
*Ответ:* Разделение нужно для безопасности и стабильности. Kernel Space (Ring 0) имеет полный неограниченный доступ к памяти и железу. User Space (Ring 3) работает в песочнице виртуальной памяти. Если программа в User Space упадет (Segmentation Fault), умрет только она. Если произойдет ошибка в Kernel Space — упадет вся ОС (Kernel Panic). Переход из User Space в Kernel Space происходит через Системные Вызовы.

**2. Что такое `initramfs` (или `initrd`) и зачем он нужен при загрузке Linux?**
*Ответ:* Это временная корневая файловая система, которая загружается в оперативную память загрузчиком (GRUB) вместе с ядром. Она нужна для решения проблемы "курицы и яйца": чтобы смонтировать настоящий жесткий диск с ОС, ядру нужны драйверы (например, для RAID, LVM или расшифровки LUKS). Эти драйверы лежат на том самом жестком диске. `initramfs` содержит минимальный набор модулей и скриптов, чтобы распознать LVM/RAID, собрать его, смонтировать настоящий `/` и передать ему управление.

**3. Как ядро передает управление программам пользователя? Какой процесс запускается самым первым?**
*Ответ:* После распаковки `initramfs` и монтирования настоящего диска, ядро ищет и запускает программу `init` (сейчас это обычно `/lib/systemd/systemd`). Этот процесс получает `PID 1`. Именно он является прародителем всех остальных процессов в системе (user space) и отвечает за поднятие сети, служб и монтирование файловых систем.

**4. Что такое Системный вызов (Syscall) и что происходит при его вызове?**
*Ответ:* Это интерфейс взаимодействия между User Space приложением и Ядром. При вызове (например, `read()`), процессор делает программное прерывание (context switch), переключается в кольцо защиты 0 (Kernel Space), ядро выполняет чтение с диска, и затем процессор возвращается в кольцо 3, отдавая данные приложению. Это "дорогая" операция в плане тактов процессора.

**5. Как работает аутентификация по SSH-ключу?**
*Ответ:* Используется асимметричная криптография. На сервере лежит публичный ключ (`authorized_keys`). Когда клиент пытается подключиться, сервер шифрует случайное сообщение (challenge) публичным ключом и просит клиента его расшифровать. Только клиент, владеющий приватным ключом, может расшифровать это сообщение математически. Он отправляет ответ серверу, доказывая, что он владелец приватного ключа. По сети сам приватный ключ никогда не передается.

**6. Зачем нужен `ssh-agent` и механизм `ForwardAgent`?**
*Ответ:* `ssh-agent` держит расшифрованный приватный ключ в памяти (чтобы не вводить пароль от ключа каждый раз). `ForwardAgent` (проброс агента) нужен, чтобы безопасно перепрыгивать с одного сервера (бастиона) на другой. Вместо того чтобы хранить свой приватный ключ на промежуточном сервере, `ForwardAgent` пробрасывает UNIX-сокет через зашифрованный туннель, позволяя конечному серверу проверить ключ, лежащий в RAM вашего локального ноутбука.

**7. Зачем нужна синхронизация времени на серверах (NTP) в микросервисной архитектуре?**
*Ответ:* Если время на серверах рассинхронизируется (clock drift), сломается проверка SSL-сертификатов (срок действия), токены авторизации (JWT expiry), распределенные транзакции в базах данных (например, Cassandra или CockroachDB используют метки времени для разрешения конфликтов) и невозможно будет правильно собрать распределенные трейсы и логи в правильном хронологическом порядке.

**8. Что делает демон `chrony` (или `ntpd`) при сильной рассинхронизации? Он просто "переводит" стрелки часов назад?**
*Ответ:* Нет, резкий перевод времени назад (step) может привести к дублированию записей в базах данных, сбоям в cron-задачах и панике таймеров внутри приложений. Вместо этого демоны (NTP/Chrony) используют "Slewing" — они слегка замедляют или ускоряют скорость хода локальных часов (тиканье), пока время плавно не синхронизируется с эталонным.

**9. Что такое Stratum в контексте протокола NTP?**
*Ответ:* Это уровень удаленности от эталонного источника времени. Stratum 0 — это аппаратные атомные или GPS-часы. Они не подключены к сети напрямую. Stratum 1 — это сервер, к которому кабелем подключены часы Stratum 0. Stratum 2 получает время от Stratum 1 по сети, и так далее (вплоть до Stratum 15, а 16 означает, что устройство не синхронизировано). 

**10. Почему при падении программы возникает `Kernel Panic`? Или не возникает?**
*Ответ:* Если упадет обычная программа в User Space (например, Nginx словит Segmentation Fault из-за неверной работы с памятью), `Kernel Panic` не возникнет — ядро просто убьет процесс (прислав SIGSEGV) и освободит память. `Kernel Panic` возникает ТОЛЬКО если критическая неустранимая ошибка (баг памяти, сбой драйвера) произошла внутри самого Kernel Space (кольцо 0), так как ядро не может безопасно продолжать работу, не рискуя повредить данные на диске.
