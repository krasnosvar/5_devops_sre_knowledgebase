# 03. Файловые дескрипторы и I/O

> Уже знакомы с темой? → [CHEATSHEET.md](./CHEATSHEET.md) — команды и шаблоны одним экраном.

## Зачем
«Too many open files», логи, которые не появляются из-за буферизации,
место на диске, которое не освобождается после `rm`, и сервер, который
держит 10 тысяч соединений одним потоком, — всё это про файловые
дескрипторы и модели ввода-вывода (blocking, select/poll, epoll).

## Пререквизиты
- [01_process_model](../01_process_model/) — процесс, fork (fd
  наследуются потомком), `/proc/<pid>/`.
- Стенд: любой Linux с bash и `lsof` (🐳 Tier 1 подходит).

## Файлы
- [CHEATSHEET.md](./CHEATSHEET.md) — шпаргалка: лимиты fd, lsof, перенаправления.
- [01_theory/fd_and_io.md](./01_theory/fd_and_io.md) — «всё есть файл»,
  таблица fd, модели I/O, select/poll/epoll, сокеты.
- [02_examples/fd_demo.sh](./02_examples/fd_demo.sh) — fd текущего shell,
  перенаправления, pipes, named pipes.
- Без отдельных упражнений: закрепляйте, запуская и модифицируя пример.

## Как проходить
1. Прочитать теорию.
2. Запустить `bash 02_examples/fd_demo.sh` и параллельно смотреть
   `ls -l /proc/<pid>/fd` и `lsof -p <pid>`.
3. Ответить на Interview Q&A без подсказки.

## Когда двигаться дальше
- можете объяснить, почему `cmd > file 2>&1` и `cmd 2>&1 > file` дают
  разный результат;
- можете найти процесс, держащий удалённый файл (`lsof +L1`);
- можете объяснить, почему epoll масштабируется лучше select.
