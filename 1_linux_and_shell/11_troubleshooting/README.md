# 11. Траблшутинг Linux

## Зачем
Итоговая тема раздела: как системно, а не наугад, разбирать
инциденты на хосте — высокая нагрузка, нехватка памяти, медленный диск,
дропы пакетов. Методологии USE/RED и 60-секундный чек-лист связывают
всё изученное (процессы, память, ФС, сеть, eBPF) в один порядок действий.

- Весь раздел: особенно [01_process_model](../01_process_model/),
  [04_filesystem_and_mounts](../04_filesystem_and_mounts/),
  [06_networking_basics](../06_networking_basics/),
  [08_performance_and_ebpf](../08_performance_and_ebpf/).
- Стенд: Linux VM с sudo (🖥 Tier 2), утилиты `sysstat`, `perf`, `bcc`.

## Файлы
- [01_theory/linux_troubleshooting.md](./01_theory/linux_troubleshooting.md)
  — USE/RED, 60-секундный чек-лист, D-state, page cache и slab, OOM
  Killer, насыщение I/O, удалённые открытые файлы, дропы в сокетах и
  conntrack, strace/perf/eBPF.
- Без примеров и упражнений: команды для отработки приведены в теории;
  воспроизводите сценарии на своей VM.

## Как проходить
1. Прочитать теорию, на своей VM прогнать 60-секундный чек-лист.
2. Воспроизвести 1-2 сценария (например, нагрузить диск `dd`/`fio` и
   найти это через `iostat -x`).
3. Ответить на Interview Q&A без подсказки.

## Когда двигаться дальше
- можете за минуту по `uptime`, `vmstat`, `iostat`, `free` сказать, какой
  ресурс насыщен;
- можете объяснить, почему load average высокий при простаивающем CPU;
- можете найти процесс, держащий удалённый файл, и причину OOM в `dmesg`.
