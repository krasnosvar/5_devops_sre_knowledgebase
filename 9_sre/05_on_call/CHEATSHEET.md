# On-Call — шпаргалка

Подробности и объяснения — в [on_call.md](./01_theory/on_call.md). ⚠️ —
опасная команда или частая ловушка.

## Ротация

| Параметр | Типичное значение |
| :--- | :--- |
| Уровни | минимум 2: первичный + вторичный |
| Размер ротации | 4–8 человек на уровень |
| Ответ первичного | 5–15 мин |
| Ответ вторичного (эскалация) | 30 мин |
| Кто в ротации | каждый инженер команды; «не умею» → научить |

| Частота смены | Плюс | Минус |
| :--- | :--- | :--- |
| Еженедельная | больше контекста за смену | тяжелее неделя |
| Ежедневная | меньше усталости | сложнее набрать контекст |

## Время реакции по severity

| Severity | Ответить | Исправить |
| :--- | :--- | :--- |
| SEV-1 / P0 | 5 мин | 1 ч |
| SEV-2 / P1 | 15 мин | 4 ч |
| SEV-3 / P2 | в рабочее время | — |
| SEV-4 / P3 | в течение недели | — |

## Метрики здоровья on-call

| Метрика | Что значит | Красный флаг |
| :--- | :--- | :--- |
| Pages на человека за смену/неделю | нагрузка | рост неделя к неделе |
| Ночные pages (22:00–08:00) | сон дежурного | > 2 за ночь несколько недель подряд |
| Ночные пробуждения | выгорание | > 2 раз в неделю |
| MTTA | алерт → ack | растёт: усталость или шум алертов |
| MTTR | алерт → восстановление | растёт: нет runbook или знаний |
| Доля алертов без runbook | готовность | > 0 для page-алертов |
| Доля времени на toil | инженерия vs рутина | > 50% |

Источник цифр — API PagerDuty / Opsgenie, не Prometheus.

## Toil

| Признак | Пример |
| :--- | :--- |
| Ручная работа | создание пользователей руками |
| Повторяется | рестарт сервиса по расписанию вместо фикса |
| Автоматизируема | ручная правка конфигов |
| Нет долгосрочной ценности | просмотр логов глазами вместо алерта |
| Растёт линейно с системой | больше сервисов → больше той же работы |

## Runbook дежурного: готовые команды

| Ситуация | Команда |
| :--- | :--- |
| Состояние подов | `kubectl get pods -n <ns>` |
| Блокировки в PostgreSQL | `psql -U app -c "SELECT * FROM pg_stat_activity WHERE wait_event_type='Lock'"` |
| Переключить провайдера через env ⚠️ (рестарт подов) | `kubectl set env deployment/<name> -n <ns> PAYMENT_PROVIDER=backup` |
| Перезапустить поды (утечка памяти, OOM) ⚠️ | `kubectl rollout restart deployment/<name> -n <ns>` |
| Посмотреть текущие env | `kubectl set env deployment/<name> -n <ns> --list` |

## Нездоровый on-call → что делать

| Симптом | Действие |
| :--- | :--- |
| Алерты без runbook | не ставить page без runbook |
| Один «незаменимый» человек | обучение, парное дежурство |
| Одни и те же инциденты | закрыть action items постмортемов |
| Страх перед сменой, нет времени на работу | посчитать pages/MTTA, пересмотреть ротацию, нанять |
| Тяжёлая неделя | компенсация: отгул после смены |
| Нет компенсации за дежурство | оформить формально |

⚠️ Если pages много неделями — чинить систему (алерты, надёжность),
а не людей.

> Проверка: команды kubectl сверены с `kubectl <cmd> --help`
> (v1.34.1, без кластера); не проверено: psql (нет локально).
