# Postmortem — шпаргалка

Подробности и объяснения — в [postmortem.md](./01_theory/postmortem.md).
⚠️ — частая ловушка.

## Когда писать

| Ситуация | Postmortem |
| :--- | :--- |
| Любой SEV-1 / SEV-2 | обязательно |
| Повторяющийся инцидент, даже низкого severity | да |
| Near-miss («почти случилось») | да |
| Команда чувствует, что могло быть хуже | да |
| Срок | в течение 48 часов, пока события свежи |

## Шаблон

```markdown
# Postmortem: <сервис> <что случилось> <YYYY-MM-DD>

## Сводка
Дата · Длительность (UTC, мин) · Severity · Затронуто (% пользователей,
функции) · Обнаружение (источник, lag)

## Влияние
Неудачные операции, деньги, жалобы, error rate vs SLO, что НЕ затронуто

## Timeline (UTC)
| Время | Событие |   — деплой, первые ошибки, алерт, ack, решение,
                       действие, восстановление

## Root Cause Analysis
### Что произошло
### Почему не поймали раньше

## Contributing Factors (без blame)

## Action Items
| # | Действие | Ответственный | Срок |

## Что сработало хорошо
## Что можно улучшить
```

## Метрики из timeline

| Метрика | От → до |
| :--- | :--- |
| Detection latency / MTTD | начало проблемы → алерт |
| MTTA | алерт → ack дежурным |
| Time to mitigate | начало → симптом убран |
| MTTR | начало → полное восстановление |

## 5 почему

```text
Проблема: payment-service отдаёт 503
1. Исчерпан пул соединений PostgreSQL
2. Слишком много одновременных запросов к БД
3. В v2.3.1 добавлен N+1 запрос
4. Code review не заметил N+1
5. Нет автоматической проверки числа SQL-запросов
→ Fix: метрика + алерт на db_queries_per_transaction
```

Не обязательно ровно 5 шагов — идти до системной причины, которую
можно исправить.

## Хороший action item

| Плохо | Хорошо |
| :--- | :--- |
| «Быть внимательнее на review» | «Добавить EXPLAIN ANALYZE в чеклист review» |
| «Улучшить мониторинг» | «Метрика `db_queries_per_transaction` + алерт > 10» |
| Без владельца и срока | `@team`, дата, тикет в трекере |

## Follow-up

| Практика | Зачем |
| :--- | :--- |
| Каждый action item — тикет (Jira, Linear) | не теряется в документе |
| Postmortem ссылается на тикеты | трассируемость |
| Ретро через 4 недели | что закрыто |
| % action items, закрытых в срок | метрика здоровья процесса |

## Ловушки

| Ошибка | Последствие |
| :--- | :--- |
| ⚠️ Имя человека как причина | blame, в следующий раз ошибку скроют |
| ⚠️ Root cause = «человеческий фактор» | система не меняется |
| ⚠️ Action items без владельца и срока | ничего не исправлено |
| ⚠️ Написать через неделю | детали timeline потеряны |
